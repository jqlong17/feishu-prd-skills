# 飞书 PRD

用本机 `lark-cli`（默认 `--as user`）创建或增量更新飞书云文档 PRD。先读本 skill，再读 `lark-cli skills read lark-doc` 及其 create/update/xml/style 引用。

**新建文档默认权限：** 创建成功后立刻设为「互联网上获得链接的人可阅读」（`external_access=true` + `link_share_entity=anyone_readable`）。

结构和密度对照 [exemplar.md](exemplar.md) 与 [参考 PRD](../../examples/reference-prd.md)。

## 何时用

- 新建飞书 PRD / 需求文档
- 改已有飞书 PRD（文案、表格、截图、章节）

## 写作原则

PRD 写给产品和研发读，要像同事写的需求，不要像模型在自我证明「写法很严谨」。

### 必须

- 写要交付什么、谁用、怎么验收。
- 用肯定句描述能力与边界：谁能做什么、数据范围是什么、失败时怎样。
- 只写上线后的目标态。不写预告横幅，不写「上线前 / 上线后」对照。
- 结构：基本信息 → 版本记录 → 需求背景 → 需求详情 → 本期不做 → 验收 → 未来版本。不要写「待确定 / TBD / Open Questions」。
- 成行成列用表格；叙述用段落；真步骤才用编号列表。
- 截图连续编号，图注写成「图 N …」。图下单独一行「线上demo入口：」加已部署的线上地址。不要写 `localhost` 或本机端口。
- 图下地址可以带产品自己的路由。不要写只为演示帧服务的内部参数，也不要在正文解释这些参数怎么配。
- 上一节已经写清这一步时，不要为凑格式在图前再重复一段。
- 没有「图 N」和对应的线上demo入口，带页面的 PRD 不算写完。
- 新增或更换截图、或改了图下地址时，把这次截图依赖的前端推到会触发线上部署的分支，并等到部署成功，再告诉用户链接可打开。部署工作流的名字以该仓库为准，不要猜。`main` 不能快进时不要强行覆盖。
- 版本默认只写 1.0。用户没声明，不要自己加 1.1。
- 不要发明产品里没有的鉴权概念。先核对现有权限模型，再写谁能进入、能看到哪一层数据。
- 数据范围用产品里真实存在的隔离概念。不要把演示配置写进需求。
- 不要写客户项目真名，也不要写驻场身份。角色用岗位，地点用「客户现场」。
- 平台里已经有的页面，本期只写怎么用到它，不把原有字段再抄一遍。

### 用户旅程

写在需求背景里。点名一个角色，写清当前限制、本期操作、失败时用户看到什么。例子里的人名和对象不能写成产品范围。

### 不要写的句子

句子如果在教作者怎么写文档，而不是在描述产品行为，就删掉。

| 不要写 | 改成 |
| --- | --- |
| 不以某页为唯一真相源 | 能力与已发布接口保持一致，随其增减 |
| 页面不应包含……以免误导 | 直接写页面有什么；范围放进「本期不做」 |
| 上线前展示预告，上线后补地址 | 删。只写上线后的能力 |
| 待确定 / TBD | 删。未决项在对话里问 |

详细正反例见 [language.md](language.md)。

## 飞书操作

### 新建

1. `lark-cli auth status --json --verify`（user 可用）。
2. 短文可一次 `docs +create`；长文先骨架再按节 `block_insert_after`。
3. 内容落盘时用 cwd 相对路径 `@file`，不要用绝对路径 `@/tmp/...`。
4. 创建成功后立刻开放链接阅读：

```bash
lark-cli drive permission.public patch \
  --params '{"token":"<document_id>","type":"docx"}' \
  --data '{"external_access":true,"link_share_entity":"anyone_readable"}' \
  --yes
```

5. 配图时截与正文一致的页面，用 `docs +media-insert` 插到对应章节，紧接着写「线上demo入口：」。

### 更新

1. 先 `docs +fetch` 回读。
2. 用 `str_replace` / `block_replace` / `block_insert_after` / `block_delete` 做增量改。
3. 不要默认 `overwrite` 全文，除非用户明确要求重建。
4. 换图后核对图注顺序和图下地址。截图或地址有变时，按上面的部署步骤处理。

## 写完自检

- [ ] 新建文档是否已设为链接可阅读？
- [ ] 有没有「真相源 / 口径 / 待确定 / 上线前」？
- [ ] 有没有客户项目真名或驻场身份？
- [ ] 有没有 `localhost`、内部演示参数？
- [ ] 图号是否连续，每张图下是否有线上demo入口？
- [ ] 新增截图或地址后，线上部署是否已经成功？
- [ ] 版本表是否仍只有用户要求的那些行？
- [ ] 列表字段是否写了来源、空值和能不能改？
