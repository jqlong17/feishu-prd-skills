# PRD 范本

写新的飞书 PRD 时，结构和密度对照仓库里的 [参考 PRD](../../examples/reference-prd.md)。不要复制它的业务对象。

## 章节

1. 基本信息
2. 版本记录（默认只留 1.0；用户没要求不加行）
3. 需求背景
   - 3.1 现状
   - 3.2 目标（编号列表，每条是上线后的能力）
   - 3.3 用户旅程（一个角色走完本期）
4. 需求详情（按使用顺序）
   - 进入
   - 主能力；并列做法分成 4.2.1、4.2.2，两条都接回后面的确认和结果
   - 确认（会改数据的动作放在确认之后）
5. 本期不做
6. 验收标准（表格）
7. 未来版本

不写「产品策略」「待确定」「上线前 / 上线后」。

## 要照着做的写法

- 数据范围用产品里真实存在的隔离概念。不要把演示配置、内部场景切换写进需求。
- 列表写成字段表：列名、怎么显示、空值、用户能不能改、在哪一步判定。分类按用户当时的选择判定，不按扩展名事后推断。
- 失败写用户看得到的结果：页面上的提示、失败的那一项怎样、其余项是否仍可用。
- 会改数据的动作写清发生在确认之前还是之后。
- 平台里已经有的页面，本期只写怎么用到它。不要把原有列表字段再抄一遍当新需求。
- 图按阅读顺序编号，图注是「图 N …」。图下单独一行「线上demo入口：」加已部署的线上地址。飞书 XML 里 `&` 写成 `&amp;`。
- 图下地址不写 `localhost`，不写只为演示帧服务的内部参数，正文也不解释这些参数怎么配。
- 上一节已经写清这一步时，图前不再重复一段说明。

## 不要从范例抄走的内容

资料柜、说明文档、表格样例是范例自己的业务。新 PRD 换自己的对象、字段和失败文案。
