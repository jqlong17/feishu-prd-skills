# PRD 语言正反例

原则：写产品行为，不写文档方法论。

## 提纲稿 vs 完整需求

| 不要这样写 | 写成旅程 |
| --- | --- |
| 支持上传、列表、预览 | 项目组成员在客户现场要把一份说明和一张表放进资料柜：从「说明文档」上传说明，从「表格样例」上传表格，在列表里预览，预览失败时新页面给出原因。 |
| 项目需要把文件管起来 | 写清谁、在什么现场、现在卡在哪，再写上线后他怎么做完这一次。 |

删掉表格和标题后，读者要能讲出「谁、在哪、做成了什么」。

## 页面和范围

| 不要这样写 | 写成需求 |
| --- | --- |
| 页面不应包含某块，以免误导研发 | 页面包含文件名称、资料类型、预览和删除 |
| 上线前用预告，上线后开放上传 | 删。只写上线后的上传和列表 |
| 不把本地演示预填写成验收 | 删。验收只写可观察的产品行为 |
| 以某页为唯一真相源 | 列表中的文件与资料柜已保存的文件一致 |

## 用词

出现就改写：真相源、产品口径、待确定、TBD、上线前、上线后、误导研发。

不要写客户项目真名，不要写驻场身份。

分类、勾选、同步要写在哪一步判定。不要用扩展名事后推断用户当时的选择。
